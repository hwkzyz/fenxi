## 2026-09-14：统一原则修正——统一思路，不强行统一数据接口

这里的“统一”只要求两个工况遵循同一套方法逻辑和判据，不要求共享同一套静态文件、传感器坐标或数值结果。每个工况保留自己的原始数据、低速模板、响应面、registration、间隙范围和独立参考；只共享动态参数定义、阶段顺序、EO 闸门、输出字段和验证门槛。

### 每次 R5 运行都必须保留旧 V1 对照

旧 V1 是每个工况的固定回归基线。新理论每次运行后，必须在相同窗口、相同传感器和相同频率定义下逐窗口比较：

| 指标 | 旧 V1 | 新理论 R5 | 报告内容 |
|---|---|---|---|
| EO | `EO_v1` | `EO_r5` | 是否一致；不一致标记 ambiguity |
| 频率 | `f_v1` | `f_r5` | `Δf` 的均值和最大值 |
| 振幅 | `A_v1` | `A_r5` | `ΔA`、相对变化率和窗口分布 |
| 波形误差 | `RMSE_v1` | `RMSE_r5` | 仅作为拟合质量指标 |

新理论不要求频率和振幅逐点等于旧 V1。旧 V1 用于回归和异常定位；若 R5 的频率或振幅发生明显变化，必须用完整波形分解和独立应变/BTT 解释，不能只凭 RMSE 变小判定改进。

此外，每个工况还必须保留一个更基础的 `fixed-gap/foundation` 版本作为第二个基线。该版本不考虑动态间隙变化，只辨识基础振动参数。最终每个窗口至少并列给出三组结果：

```text
Foundation（不考虑间隙变化）：      f_foundation, A_foundation
旧 V1 gap-aware：                    f_v1, A_v1
新理论 R5：                          f_r5, A_r5
```

三者应使用同一窗口编号和同一频率定义。第一阶段只报告频率和振幅，不把 RMSE 或 `dg_s` 混入主比较表；RMSE、间隙增量和独立参考放在后续审计表中。这样可以分别看出：引入旧 V1 的间隙处理带来了什么变化，以及新理论相对旧 V1 又带来了什么变化。

## 2026-09-14：最终程序结构与强制可视化输出

最终程序不再按“一个大脚本直接给出 EO/A/RMSE”组织，而按四个可独立检查的阶段组织：

### Stage 0：三路基线准备

对每个工况、每个相同窗口，读取或生成：

1. `Foundation/fixed-gap`：不考虑动态间隙变化；
2. 旧 V1 `gap-aware`：原有间隙变化方法；
3. 新理论 R5：冻结静态模型后的完整波形方法。

Stage 0 只负责保证三个结果的窗口、传感器、时间/空间坐标和频率定义一致，不允许在此阶段调 R5 参数。

### Stage 1：静态合同和冻结

工况专用 adapter 负责低速原始波形、模板、响应面、registration、基准间隙和增益。必须通过：

- 低速多圈重复性；
- 低速模板 replay；
- 响应面支持率；
- `F_x`/`F_g` 有限性；
- 间隙传感器角色检查。

通过后生成不可修改的 `FrozenStaticModel`。动态程序不能重新估计静态倾斜、registration 或模板坐标。

### Stage 2：动态识别

统一公共引擎只接收 `FrozenStaticModel` 和高速窗口，先做 VP/seed EO 候选，再做固定 EO 的完整波形拟合。动态自由参数仅为：

```text
EO, A, phi, dx, dg_s
```

其中 `dg_s` 只对该工况声明为 gap sensor 的通道启用。

### Stage 3：比较与审计

自动生成 Foundation、旧 V1、R5 三组频率/振幅，并进行逐窗口比较；随后再生成 RMSE、支持率、`dg_s`、EO margin 和独立应变/BTT 审计。独立参考只能后验使用。

### 每次运行强制生成的图

每个工况至少输出以下 8 类图，缺一项就不能标记该次运行为 complete：

1. `A0_low_speed_repeatability`：低速多圈原始波形、均值和离散带；
2. `A1_static_response_family`：静态模板族/响应面及有效支持域；
3. `A2_low_speed_replay`：低速实测与冻结模型重放、残差；
4. `B0_high_speed_input`：高速多圈输入，禁止跨转次连线；
5. `B1_static_gap_vibration_decomposition`：静态、gap-only、full-wave、实测四条波形；
6. `B2_eo_profile_and_vp`：VP 位移、EO 候选曲线和 Top1–Top2 margin；
7. `B3_full_wave_residual`：Foundation/V1/R5 与实测波形、逐传感器残差；
8. `C0_baseline_frequency_amplitude_comparison`：三种方法的频率和振幅逐窗口对比及差值。

图中必须按转次分段绘制，不能把不同转次首尾连接。每张图写入工况、窗口、方法版本和数据来源；图只读结果文件，不反向修改拟合参数。

### 最终判定

```text
Stage 1 静态审计通过
    ↓
三路频率/振幅可比
    ↓
R5 与旧 V1/ Foundation 的变化有波形证据
    ↓
独立参考后验通过
    ↓
该工况才标记为 validated
```

### 推荐运行顺序

1. 先运行该工况原有旧 V1 主链，冻结并导出窗口级 `EO_v1/f_v1/A_v1`；
2. 运行该工况自己的静态 adapter，完成低速 replay、响应面支持率和 registration 审计；
3. 将冻结静态模型交给同一个公共 R5 动态引擎，动态阶段只估计 `EO,A,phi,dx,dg_s`；
4. 用 VP/seed 形成 EO 候选，执行 EO consistency gate，再做固定 EO 的完整波形拟合；
5. 自动生成 R5–V1 逐窗口比较表以及频率/振幅差异图；
6. 最后运行独立应变/BTT 后验验证，独立参考不得参与候选选择或调参。

### 判读顺序

```text
EO 一致性 → 频率差异 → 振幅差异 → 波形分解 → 独立参考
```

今后的每次 20250527 或 20251222 运行，都必须同时回答：新理论是否保持了相对旧 V1 的合理连续性；若改变了频率或振幅，是否有静态模型、gap/vibration 分解和独立参考支持。
