# R2/R3/R4 主程序索引（2026-09-16）

本文件夹目前有两层“主程序”概念，容易混淆：

主程序的写法已按试验脚本的习惯统一：入口文件采用“参数配置→路径→运行前检查→一次正式计算→结果回显”的直线结构。复杂数值运算仍保留在少量有明确输入输出的子程序中；不把每一行再包装成一层函数，以保证代码可读、可调试且不重复实现算法。

1. `R2/R3/R4` 是论文验证路线；
2. `Route 30` 是通用低速/高速间隙—振动识别器。

两者共用动态盲辨识后端，但不是同一个实验问题，不能互相替代。

## 论文验证路线：唯一正式入口

| 路线 | 唯一正式入口 | 响应面适配 | 正式输出 |
|---|---|---|---|
| R2 | `Run_R2_BlindSingleFrequency.m` | 同几何直接响应面 | `r2_profiled_recovery/output/unified_blind_backend` |
| R3 | `Run_R3_BlindSingleFrequency.m` | 同一响应面族内留出间隙状态 | `r3_heldout_recovery/output/unified_blind_backend` |
| R4 | `r4_pc1_manifold_transfer/blind_unknown_gap/Main_10_UnifiedBlindBackendValidation.m` | 多响应面之间的 PC1/系数流形迁移 | `r4_pc1_manifold_transfer/blind_unknown_gap/output/unified_backend_full` |

批量重跑三条路线使用：

```matlab
Run_Formal_Blind_R2_R3_R4_Batch
```

`Run_R2_UnifiedBlindBackend.m`、`Run_R3_UnifiedBlindBackend.m` 和
`Main_10_UnifiedBlindBackendValidation.m` 是上述入口调用的实现层，不应作为
另一个主程序单独解释结果。

## 三条路线真正统一的部分

三条路线均调用 `local_func/run_unified_blind_dynamic_backend.m`，并遵守：

`VP/EO 候选 -> 振动位移预拟合 -> 间隙、dx、幅值、相位重新优化 -> 完整电压波形 SSE 排序`。

VP 只提供频率/EO 候选，不能提供最终振幅或相位先验。动态阶段不重新估计
低速静态状态；R4 的 PC1 只改变响应面适配器，不改变辨识器。

## 三条路线不相同的部分

- R2 是同一响应面上的机制验证；
- R3 是同一固定几何响应面族内、未参与校准的间隙节点恢复；
- R4 才是多个倾角/几何响应面之间的 PC1 响应面迁移和几何失配验证。

因此不能把三者的误差或成功率直接当作同一种工况的重复实验。

## 当前统一性结论

代码接口已经统一，科学验证尚未完全闭合。此前 R3 的失败判断不严谨：统一烟雾
脚本使用了 `EO=[7,10,13]` 和非零 `deltaF`，而 R3 冻结协议是固定
`eoTrue=10`、`deltaF=0`。因此该烟雾结果不能证明 R3 的同一响应面间隙恢复失败；
应按冻结协议重跑后再评价。R3 的“留出”指间隙节点留出，不是响应面迁移。

## 其他入口的定位

- `run_inv_log_2_main_method.m`、`run_inv_log_2_low_high_main.m`：通用 Route 30 主程序，不是 R2/R3/R4 论文路线入口。
- `run_inv_log_2_structured_main.m`：已知频率结构（single/dual sync/async）入口，用于结构化仿真，不是盲 EO 主入口。
- `r2_profiled_recovery/Run_R2_ProfiledMechanism.m`、R3 的 `Run_00`--`Run_05`、R4 的 `Main_01`--`Main_07`：机制、标定、静态面和审计程序；只有各目录 README 标为 formal 的文件才进入论文主结果。
- `30_low_high_gap_fast_bridge`：Route 30 历史/效率/双频验证目录；`low_high_gap_fast_bridge`：当前 low-increment 更新和验证目录。两者都不是 R2/R3/R4 的唯一入口。
- `local_func`：底层函数库，禁止直接作为分析入口。
